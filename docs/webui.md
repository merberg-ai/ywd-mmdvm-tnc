# Passive packet WebUI

The experimental YWD WebUI is a separate read-only observer for the physically-qualified monitor-events plane. It is intentionally outside the modem/TNC/RF path.

## Boundary

The WebUI reads only:

- live schema-1 NDJSON from `127.0.0.1:8002`;
- historical structured logs from `/var/log/ywd-packetlog/YYYY-MM-DD.jsonl`;
- historical human logs from `/var/log/ywd-packetlog/YYYY-MM-DD.log`.

It does **not** open TCP KISS, AGW, the modem UART, GPIO, firmware tooling, TX admission, channel-access, or RF objects. The HTTP API implements GET endpoints only. There is no WebUI transmit/control endpoint.

The qualified monitor source remains the backpressure boundary. A slow WebUI process can lose monitor events without blocking packet RX/TX. Inside the WebUI, each browser SSE client gets another bounded queue; a slow browser can likewise lose UI events without blocking the monitor reader.

## Process layout

```text
ywd-tncd
  |
  +-- qualified monitor :8002 (read-only NDJSON)
         |                         \
         |                          +-- ywd-packetlog --> daily .jsonl/.log
         |
         +-- ywd-webui --> HTTP/SSE :8088 --> browser
```

`ywd-webui.service` is separate from both `ywd-mmdvm-tnc.service` and `ywd-packetlog.service`. Stopping or restarting the WebUI has no role in modem ownership or RF lifecycle.

## HTTP API

```text
GET /api/v1/status
GET /api/v1/recent
GET /api/v1/stream        Server-Sent Events
GET /api/v1/dates
GET /api/v1/history
GET /api/v1/stats
GET /api/v1/human-log
GET /                     static WebUI
```

No POST/PUT/PATCH/DELETE handler exists.

Useful history query parameters:

```text
/api/v1/history?date=2026-09-10&limit=250
/api/v1/history?date=2026-09-10&event=rx.frame
/api/v1/history?date=2026-09-10&event=tx.*
/api/v1/history?date=2026-09-10&station=KJ6YWD-11
/api/v1/history?date=2026-09-10&q=hello
```

History dates are strictly validated as `YYYY-MM-DD` before a path is constructed.

## Live identity

Monitor `seq` is only monotonic for the current `ywd-tncd` process. The WebUI adds `_web_generation` to live browser copies and identifies SSE events as:

```text
<web-monitor-generation>:<monitor-seq>
```

The generation increments each time the WebUI reconnects to the monitor. It is display/session metadata only and is never written back to the qualified monitor or packet logger.

## UI

The interface is dependency-free: no CDN, remote fonts, analytics, or browser frameworks are required. It uses a terminal-style system monospace stack and a YWD dark cyber theme with scanlines, glow, live RX/TX animation, monitor/SSE spinners, lifecycle visualization, history, statistics, frame inspection, raw JSON, frame hex, and the existing human packet-log format.

Animations obey `prefers-reduced-motion`.

## Install and enable

The low-level product installer places the WebUI package, service, and safe loopback-only configuration but **does not enable or start the WebUI automatically**.

Default configuration:

```text
/etc/ywd-mmdvm-tnc/webui.toml
```

Default browser endpoint:

```text
127.0.0.1:8088
```

For a trusted LAN test, explicitly change the web block to:

```toml
[web]
listen = "0.0.0.0"
port = 8088
allow_wildcard_bind = true
```

The monitor source remains loopback-only.

Then:

```bash
sudo systemctl enable --now ywd-webui.service
sudo systemctl status ywd-webui.service
sudo journalctl -u ywd-webui.service -f
```

The WebUI bind validator accepts IPv4 loopback/private addresses and explicitly-authorized `0.0.0.0`; direct public-address binds are rejected.

## Host qualification

Run:

```bash
bash scripts/check-webui.sh
```

The host gate verifies Python compilation, unit tests, safe config defaults, explicit wildcard opt-in, loopback-only monitor source, bounded SSE fan-out, HTTP/SSE behavior, lack of HTTP mutation handlers, absence of modem/KISS/TX imports and monitor socket write APIs, systemd hardening, framework self-test inertness, and no changes to the qualified modem/monitor path relative to the `dev-webui` base checkpoint.

## Physical test boundary

After host qualification is green, install the branch on the real Pi and run:

```bash
sudo bash /opt/ywd-mmdvm-tnc/source/scripts/webui-physical.sh
```

The physical gate is observation-only. It does not create KISS frames or request RF transmission. It checks the installed WebUI API and waits for an ordinary live monitor event generated by normal station/network activity. Visual/browser verification is then performed from a LAN browser.
